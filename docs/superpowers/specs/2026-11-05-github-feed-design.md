# GitHub Feed 设计

日期：2026-11-05
状态：已确认。用户随后授权一次性完成开发与验证，不再逐阶段等待设计确认。

## 目标与范围

为个人持续接收 GitHub 新信息并学习提供一个公开网站。每日表示更新频率，不限定每日收录量或阅读量。项目不限技术方向；通过 Star、时间和真实版本事件帮助发现值得学习的内容。

首版包含列表、详情、搜索、排序、浏览器收藏与已读，以及自动发现、版本跟踪、中文学习内容生成。历史项目持续保留，支持分页浏览。

首版不包含用户注册、跨设备同步、社区互动、消息推送、向量搜索和在线对话。网站公开可读，收藏与已读只保存在当前浏览器。

## 架构

- Next.js App Router + React + TypeScript strict：列表与详情，部署到个人 Vercel 空间。
- GitHub Actions：每日定时运行独立脚本，另提供手动运行入口；不需要打开个人电脑。
- Neon PostgreSQL：保存共享内容、事件、快照和任务进度，优先免费套餐。
- 0G Router API：后台生成学习内容，模型结果持久化，访问页面不触发付费推理。
- 浏览器 localStorage：保存收藏、已读，提供 JSON 导出和导入。

每日流程：发现候选 → 同步项目与版本元数据 → 保存 Star 快照 → 获取原始资料 → 分批生成解读 → 校验 → 发布内容 → 页面读取更新。

GitHub Actions 仅写数据库，不自动提交数据到代码仓库。网页不提供公开的模型调用或任务触发接口。

基础设施优先免费额度；额度有限，超额不自动升级付费套餐。AI 费用由用户提供的 0G API 承担，仍需记录用量并限制单任务运行时间、输入规模、输出规模和重试次数。

## 列表与信息流

首页提供「最新信息」「项目榜单」「收藏」入口。最新信息包括新收录项目和已收录项目的新正式版本；项目榜单以项目为单位，避免同项目多个版本重复占位。

卡片展示名称、中文一句话介绍、推荐或更新原因、语言、累计 Star、事件类型、时间与收藏操作。内容生成中的项目展示真实元数据和处理状态，不伪造学习解读。

支持名称、仓库路径和介绍的关键词搜索；支持 Star 范围、语言、时间范围、已读状态筛选。用户没有方向限制，语言筛选仅为可选浏览工具，不限制后台收集。

排序使用可解释的明确字段：

- 最新信息：按首次收录时间或正式版本发布时间降序。
- 最多 Star：按最近采样的累计 Star 降序。
- 最新创建：按仓库创建时间降序。
- 最近推送：按 GitHub 的 pushed_at 降序，单独标明它不代表重要版本更新。
- Star 增长：按两个有效每日快照的差值排序，同时展示区间；积累足够数据后支持七日区间。

没有区间基线时增长值为未知，不显示为零，不外推成七日增长。排序相同时用稳定标识作为次级排序字段。分页不限制历史可访问条数。

时间字段分别记录仓库创建、代码推送、版本发布、首次收录、最后同步与解读生成时间，不互相替代。每日分组按 Asia/Shanghai 展示，数据库时间统一保存为 UTC。

## 项目发现与版本跟踪

使用 GitHub 官方 API，按创建时间区间、Star 区间拆分搜索，覆盖高 Star 经典项目及近期创建且已有关注的新项目。不声称完整扫描全 GitHub；记录每次发现范围和分页覆盖情况。

初始候选策略：累计 Star 不低于 1,000 的项目，以及最近 90 天创建且 Star 不低于 100 的项目。阈值保存在后台配置中，可依据实际噪声调整；不做面向用户的配置中心。

默认排除 fork、归档、禁用和空仓库。首轮补入历史候选，后续增量发现、轮转补充历史区间，避免每天只检查同一批搜索头部。

对已收录项目轮转同步元数据及 Releases。首版将新的正式 Release 作为可核验的版本事件，排除 draft 和 prerelease；普通提交不自动生成「重要更新」。版本解读说明本次实际变化，不把所有 Release 宣称为重大技术突破。

首次发现时，已有最新 Release 仅作为项目背景基线，不额外制造一条历史更新事件。后续新 Release 才形成独立事件。

使用 GitHub 稳定仓库 ID 去重，名称和路径可更新。版本事件用仓库 ID 与 Release ID 唯一约束去重。

尊重 API 速率限制与 Retry-After，分页与任务进度可续跑。单次任务有有界批量与时间预算，未处理项目保留到后续任务；不限制用户阅读，也不承诺每天无限量处理。

## 学习详情与内容标准

项目详情展示最新有效学习内容，附项目元数据、来源、收藏入口和历史版本事件。版本事件通过独立详情地址提供稳定链接，保留当次更新语境。

学习内容包括：

1. What：目标用户、解决的问题、具体使用场景。
2. Why：价值、值得借鉴的思路、适用条件与局限。没有对照证据时不做优越性断言。
3. How：官方推荐的最小上手路径、核心流程，以及已核验的源码阅读入口。
4. 学习要点：可以迁移的知识点与一个可选动手练习，不要求每天完成固定数量。
5. 依据：原始链接、资料抓取时间、生成时间、模型和内容版本。

版本详情额外解释具体变化、受影响的使用方式，以及现有使用者是否需要采取行动。普通项目页与版本详情共享内容结构，不复制维护两套项目资料。

先读取 README、正式版本说明和相关官方文档；需要解释内部实现时再读取关键源码。源码链接固定到读取时的 commit，Release 链接固定到版本；保留输入资料身份以便追溯。

区分资料直接支持的事实与模型分析。输入缺失、截断或无法确认的行为明确说明，不补造运行结果、兼容性、性能、命令、文件路径或 API。首次生成不运行第三方仓库代码。

生成后校验必需字段、长度、URL、仓库引用与源码路径。校验失败进入重试或失败状态，不发布为已完成内容。格式校验不能保证事实正确，发布前需完成真实样例人工抽查。

项目内容采用结构化数据渲染；不执行仓库或模型提供的 HTML、脚本和指令。外部资料作为不可信输入，不允许其改变任务或获取密钥。

## 模型接入与选择

0G 接口使用 https://router-api.0g.ai/v1。通过服务端环境变量配置 API Key 和模型 ID；准确模型 ID 在接入时以官方接口返回为准，不用展示名猜测。

初始候选为目录中的 GLM-5.3 与 Claude Sonnet 5。用同一组真实项目及版本更新比较来源忠实度、实现解释、中文表达、结构稳定性、耗时和用量，再选择默认模型。当前尚未执行付费调用，未证明任一模型更合适。

不因单次失败自动切换到未评估的模型。保存输入摘要、提示词版本、模型和 token 用量；资料或生成策略未变时复用已发布结果。新生成失败时继续保留上次有效版本，并展示其时间。

## 数据结构

- repositories：GitHub ID、owner/name、描述、语言、Star、fork/归档状态、各类时间与同步进度。
- repository_snapshots：仓库 ID、UTC 采样日、采样时刻、累计 Star；仓库与采样日唯一。
- feed_events：新收录或 Release 事件、发生时间、首次观察时间、Release ID、对应仓库。
- learning_contents：关联事件、结构化解读、版本、状态、输入摘要、模型、提示词版本、用量、生成时间与错误摘要。
- content_sources：关联内容、原始地址、来源类型、读取时间、commit 或版本身份及资料摘要。
- collection_runs：发现范围、游标、运行状态、处理与失败计数、起止时间及有界错误摘要。

事件存在不代表解读完成。内容状态至少区分 pending、processing、ready、failed、insufficient_sources。处理中任务设过期租约；任务中断后可恢复，不永久卡住。

只向页面返回公开字段；密钥、数据库连接信息、原始错误堆栈和敏感请求信息不返回浏览器。

## 浏览器收藏与已读

收藏以稳定仓库 ID 标识；已读以信息流事件 ID 标识，因此收藏项目收到新版本后仍可显示为未读。首次进入有效详情后标记已读。

存储格式带版本号，处理损坏、不可用和容量异常；导入只接受有界、结构合法的数据。清除浏览器数据会清除个人状态，界面提供简短说明与导出入口。

## 视觉与交互

采用阅读优先的简洁布局、清晰文字层级和紧凑列表；桌面支持扫描比较，手机可完整阅读详情。首版使用中文界面，保留项目原名与技术名词。

列表保留筛选和分页 URL，返回时恢复浏览位置。提供加载、无结果、暂无内容、内容处理中和失败提示；显示最近成功更新及数据时间，避免旧数据看起来像刚刚更新。

交互支持键盘、可见焦点和可辨识的收藏状态。技术运行细节仅在影响内容可靠性时展示给读者。

## 验收与实施约束

- 用真实项目确认列表、搜索、排序、分页、项目与版本详情可用。
- 刷新后收藏与已读保留；导出后可在另一浏览器导入。
- 相同收集批次重复执行不重复创建事件或有效解读。
- 新版本形成新事件，生成失败不破坏已有内容；任务中断后可续跑。
- Star 基线不足时显示未知，已有基线时差值和区间可核验。
- 真实样例能从 What / Why / How 回到原始资料，明确区分来源事实和分析。
- 运行 npx tsc --noEmit 及已配置的 npx eslint . --quiet，修复全部错误。
- 按用户要求不新增自动化测试；使用类型检查、静态检查和授权后的实际流程验证。
- 验证公开网页不泄漏密钥，部署后确认真实定时任务及数据库写入结果。

实施按明确职责拆分，涉及超过 5 个独立文件时使用子代理。按用户最新授权持续完成开发与验证，不再逐阶段等待；外部服务凭据和远端写入授权独立处理。

安装新依赖、启动开发服务或构建进程，以及创建外部服务需取得相应授权。Git 本地写操作与远端 push 按用户规则单独确认；不自行提交设计文档。

实施计划记录具体文件清单、依赖清单和验证步骤。上线前完成可审阅成果，部署与远端写入按实际授权范围执行。
